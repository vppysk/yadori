# オーダーの改修（2026-09-27 決定）

plan 4.2 のオーダーチケットを、運用しやすい形に改める。メモの論点と決定、実装の要点をまとめる。

## 1. 品目マスタ

- 品目はゲストが選べる単位（フェイスタオル、バスタオル…）で持ち、**分類**（タオル、アメニティ…）を付ける。分類はゲスト画面・フロントの選択欄のまとまりと、ゲストの言い方の照合に使う
- 設定は管理PC `/admin/items` で直接編集する。館内の情報の資料フロー（読み取り→承認）には乗せない。品目は重み・担当の役割を持つ運用の設定で、期間で変わる案内情報とは性質が違うため
- 別名は任意の補助として残す（スタッフが網羅しなくてもよい。分類の照合とゲストの選択で補う）

## 2. 受付の流れ

### ゲスト（AIチャット）
1. ルーター（LLM）はゲストの言い方の品名・数量、**備考**（使い道など、オーダー係に伝えること）、**希望日時**（本日／明日＋時刻）を読み取るだけ
2. 品目との照合はコード（`src/server/order-match.ts`）。品目名・別名が一致→その品目、分類に当たる→その分類の品目をすべて候補、部分一致→当たった品目を候補。当たった品目の同じ分類の品も数量0で並べる
3. ゲスト画面に選択欄（品目ごとの数量・備考・お届け時間）を出す。ゲストが確定した時点でLLMを通さずにチケットを作る（`order_drafts` → `tickets`）
4. オーダーだけの発言は、回答係（LLM）を呼ばずに定型文で返す

例）「タオルください」→ 分類「タオル」→ 選択欄に「フェイスタオル 0／バスタオル 0」→ ゲストが数量を選んで確定

LLMに照合までさせると誤った（別名にある品をないと判断、ない品を既存品目に当てはめる。2026-09-25）。候補を広めに出して最後はゲストが選ぶので、照合の誤りはゲストが直せる。

### フロント（電話・来訪）
- 自由文の読み取りは廃止。部屋・分類ごとの品目と数量・備考・お届け時間を選び、割り当て予定を確認してから登録する

### 備考
- チケット単位の自由記述（例: ライター1個、備考「誕生日で部屋でケーキに火をつけるため」）。ゲストの発言からはルーターが下書きし、ゲストが選択欄で直せる。現場スマホ・オーダーボードに表示する

## 3. 担当（担当席）

- 担当は個人アカウントではなく、**枠ごとの担当席**（共有アカウント。例: 「ハウスキーピング 12〜15F ①」）でもよい。管理PCで枠の**人数**を決めると、席のメンバーを自動で作る（`members.seat_slot_id`）
- 席はその枠だけの「担当になれる」と、AIに相談・引き継ぎに対応の権限を個別に持つ。端末でその席としてログインし、出勤→退勤で使う。人数を減らすと番号の大きい席から無効にする
- 公平性（担当量pt）は席単位で説明する。席を誰が使ったかは既存のシフト管理側で持つ（このシステムでは持たない）
- 個人アカウントでの出勤もそのまま使える（応援・上長など）
- 役割×エリアの2段は残す。役割＝品目のまとまり、エリア＝部屋のまとまり。枠に品目・部屋を直接結ぶと、品目を足すたびに全枠を直すことになるため

## 4. 部屋

- 部屋は予約・客室管理システムの一意のID（`rooms.id`）で持つ。表示は棟＋部屋番号（例: 「別館 105」）。本館・別館で同じ番号があっても区別できる
- エリアはフロアの範囲ではなく、部屋ごとに `rooms.area_id` で持つ。管理PCでは棟・フロアごとにまとめて割り当てる
- チケットは `room_id` で部屋を指し、`room_number` には表示名を保存する（引き継ぎ・通知などの表示はこれまでどおり）
- 同じフロアのまとめは、同じ棟の同じフロアで判定する

## 5. 期限と時間指定

- 品目の期限（分）は「できるだけ早く」のときの目安として残す。期限切れのクレーム予兆への昇格（デモ場面5）も残す
- チケットに**希望日時** `requested_for` を持てる。希望日時のあるチケットは、その「割り当ての前倒し（分）」（ホテルの設定、既定30分）前まで割り当てを保留し、定期実行（`/api/cron/tickets`）で割り当てる（`dispatched_at`）。期限は希望日時
- ゲスト画面は「目安 ○分以内」の代わりに「○時○分にお届け予定」を出す

## 6. 在庫・取り扱いの状態

在庫数は持たない（既存システムとの二重管理を避ける）。品目の状態を3つにする。

| 状態 | ゲスト画面・AI | フロント |
|---|---|---|
| 取り扱い中 | 選べる | 選べる |
| 一時品切れ | 選択欄に「品切れ中」で出し、選べない。はっきり頼まれた品が品切れなら「ただいま品切れ」と伝え、スタッフに確認を依頼する（B案） | 選べない |
| 取り扱い終了 | 存在しない扱い（A案）。頼まれたら取り扱いのない品として扱う | 出さない |

- 取り扱いのない品・品切れの品を頼まれたら、引き継ぎ（`order_unavailable`）を作り、スタッフが代わりの品などをゲストに連絡する
- 既存システムの在庫と連動する場合は、予約・客室管理システムのMCPに在庫を読むツールを足し、状態に変換する（将来。設計のみ）

## 7. スコープ外

- 電話などゲストとの会話中に、LLMでフロントの入力を補助すること
- 在庫数の管理、既存の在庫システムとの連動
